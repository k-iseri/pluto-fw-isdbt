# v2 設計メモ — 復調処理の段階的な FPGA 移行

2026-10-14 起草。v1（8bit 転送 + サンプルカウンタ、[design-v1.md](design-v1.md)）で USB 2.0 の帯域問題は
解決したので、v2 の目的は **ホスト CPU 負荷の削減**（非力な PC での視聴・録画、将来の TS 直接出力）になる。
対象は引き続き HamGeek PlutoSDR Nano（XC7Z010）。7010 に全部は載らないので、
ホスト側 BonDriver が「ファームの申告する能力」で経路を選ぶ前提（README「互換性」）で段階的に進める。

## 1. 判断材料（実測、2026-10-14）

### ホスト復調の CPU 内訳

`ISDBT_PROFILE=1 isdbtd --sigmf`（8bit ファームの実波録音 5 秒、Mode 3 GI 1/8、A: QPSK 2/3、B: 64QAM 3/4）:

| 段 | 内容 | 時間（4.8 秒分の信号に対して） | 割合 |
|---|---|---|---|
| front | 同期（GI 相関・CFO・クロック追従）、FFT 8192、チャネル推定・等化、周波数/時間デインターリーブ | 2.53 s | 47% |
| soft | 軟判定（デマップ）、ビットデインターリーブ | 0.75 s | 14% |
| fec | ビタビ（K=7、パンクチャ）、RS(204,188) | 2.12 s | 39% |

合計 5.4 s / 4.8 s ≈ 1.1 コア（2 スレッドで重ねているので実時間は追いつく）。

### 7010 の資源（v1 r3、公式設計 + pack8 + カウンタ、TX 経路込み）

| 資源 | 使用 | 容量 | 使用率 | 内訳のあたり |
|---|---|---|---|---|
| LUT | 12,980 | 17,600 | 74% | axi_ad9361 コア 10.8k（RX/TX チャネル、DDS、IQ 補正、DC フィルタ、遅延制御） |
| FF | 22,546 | 35,200 | 64% | 同上 15.9k |
| BRAM36 | 2 | 60 | 3% | ほぼ空き |
| **DSP** | **72** | **80** | **90%** | コア 28（DDS・IQ 補正・DC フィルタ）、**FIR（RX デシメータ + TX インターポレータ、各 2ch）≈ 44** |

→ このままでは何も載らない。FIR は AD9361 の最低レート（2.08 MSPS）未満で使うためのもので、
本用途（8.127 MSPS）では一度も使われない。

### 2a（スリム化）後の実測（2026-10-14、hdl フォーク isdbt）

| 資源 | v1 r3 | **2a** | 空き |
|---|---|---|---|
| LUT | 12,980（74%） | **6,227（35%）** | 11.4k |
| FF | 22,546（64%） | **10,418（30%）** | 24.8k |
| BRAM36 | 2 | 2 | 58 |
| DSP | 72（90%） | **0** | 80 |

FIR ×2 と DDS / IQ 補正 / DC フィルタで DSP を全部使っていた。実機: ad9361 一発 probe、MER 25.0 dB、
90 秒で bad 0 / hw_dropped 0、AD936x 温度 36.8 → 35.1 °C。2b の見積もり（LUT ~8.5k、DSP 28〜40、BRAM ~41）は
**7010 に収まる**見通しになった。

## 2. 段階

| 段階 | 内容 | ホストの入口 | 申告ビット | 狙い |
|---|---|---|---|---|
| **2a** | **スリム化**: FIR ×2 と関連ロジック削除、DAC 側の DDS / IQ 補正 / DC フィルタ無効化。インターフェースと DMA は残す（ad9361 ドライバのデジタル I/F チューニングは TX→RX のチップ内ループバックに FPGA の PN 生成器を使うので、TX インターフェースは消せない） | 変化なし（I/Q 8bit） | 変化なし | v2 の土台。消費電力・温度も下がる |
| **2b** | **前段オフロード**: 同期（GI 相関、CFO 補正、サンプルクロック追従）、FFT 8192、散布パイロットによるチャネル推定と等化、TMCC 復号を FPGA で行い、**等化済みデータキャリア（I/Q 各 8bit）+ チャネル品質（8bit）+ シンボルヘッダ**を DMA で出す | 新規: キャリア列から周波数/時間デインターリーブ以降 | bit2 = carrier output | ホスト CPU −47%、USB 転送は 4992 キャリア × 3 B / 1.008 ms ≈ 14.9 MB/s（8bit I/Q の 16.3 MB/s より少し減る） |
| **2c** | **後段オフロード → TS 直接出力**: 時間デインターリーブ（最大 I=4、数 Mbit → PS 側 DDR を DMA で使う）、デマップ、ビットデインターリーブ、ビタビ、RS、TS 再構成（階層合成、ヌルパケット） | 新規: TS をそのまま流す（isdbtd の --ts 経路と同じ） | bit3 = TS output | ホスト CPU ≈ 0、USB ≈ 2 MB/s。**7010 では BRAM/LUT が足りない公算が大きく、Zynq-7020 機（Pluto+ / LibreSDR）が本来の土俵** |

2b を飛ばして 2c に行かない理由: 2b の出力（等化済みキャリア）は ISDB-T の処理連鎖の中で境界が明確で、
ホスト側にも同じ境界（`EqualizeAndDeinterleave` の出力 `Xt`/`Wt`）がある。2c は DDR を使うインターリーバと
FEC で規模が一段大きく、7020 機のピン配置調査からやり直しになる可能性が高い。

ISDB-C（ケーブル）は当面ソフト復調のまま（64QAM 単一キャリアの復調器を別途 FPGA 化する必要がある）。
BonDriver はファームの申告を見て、地デジは FPGA、ケーブルはソフトという混在で動く。

## 3. 2b の見積もり（7010、2a 後）

| ブロック | 方式 | LUT | DSP | BRAM36 | 備考 |
|---|---|---|---|---|---|
| 同期 | GI 相関（遅延 8192 サンプル）、CFO は相関位相 + TMCC/パイロットで整数部、CORDIC で回転 | ~1.5k | 4 | 6 | 8bit I/Q なので遅延線は 16 KB |
| クロック追従 | 整数サンプルスリップ + 等化後位相補正（ホストと同じ方式） | ~0.5k | 0 | 0 | AD9361 のレート設定は整数 Hz なので公称 8,126,984.127 Hz に対し −15.6 ppm 固定ずれがある。追従で吸収 |
| FFT 8192 | Xilinx FFT IP、pipelined streaming、16bit | ~3k | 16〜24 | 12 | 1 シンボル 1.008 ms 中に 8192 点 → 8.2 MHz クロックで足りる（100 MHz で余裕） |
| チャネル推定 / 等化 | SP（12 キャリアに 1 本、4 シンボル周期）の時間→周波数線形補間、複素除算は逆数 LUT + 乗算 | ~2.5k | 8〜12 | 20 | パイロット履歴 4 シンボル × 5617 キャリア |
| TMCC / AC 復号 | DBPSK 差動復号、同期語・パリティ | ~0.5k | 0 | 1 | フレーム境界と階層情報をヘッダで出す |
| 出力整形 | シンボルごとに 4992 キャリア × (I,Q,CSI) + 16 B ヘッダ → cpack 相当の DMA | ~0.5k | 0 | 2 | |
| 合計 | | ~8.5k | 28〜40 | ~41 | 2a 後の空き（LUT ~7k、DSP ~60、BRAM ~58）に対し **LUT が厳しい**。IQ 補正・DC フィルタの無効化と RX チャネル 2/3（未使用）の削除で +2k 程度稼ぐ |

語長（2026-10-14 に決定、isdbt-sdr ブランチ fw-v2b の `tools/fe_quant_study.py` で実波録音を評価）:

| 変種 | MER A（QPSK） | MER B（64QAM） | RS 訂正不能 A / B |
|---|---|---|---|
| 浮動小数点（ref/） | 22.83 dB | 25.74 dB | 11/512, 11/23328（録音先頭の立ち上がり分、全変種で同じ） |
| FFT 出力 16bit | 22.83 | 25.74 | 同じ |
| FFT 16bit + 等化出力 I/Q 8bit + CSI 8bit | 22.88 | 25.68 | 同じ |
| FFT 12bit + 8bit 出力 | 22.88 | 25.68 | 同じ |
| FFT 10bit + 8bit 出力 | 22.88 | 25.67 | 同じ |

→ **キャリア出力は I/Q 各 8bit（フルスケール ±2.0、64QAM の格子間隔 ≈ 20 LSB）+ CSI 8bit（0〜4.0）で十分**。
FFT は DSP に余裕があるので 16bit（Xilinx FFT IP の scaled 固定小数点）で回し、量子化の心配を
等化側に持ち込まない。FFT 出力のブロック浮動小数点近似なので、実装では各段の丸めをビット一致モデル
（ref/ に固定小数点版を追加）で確認する。残る未決は等化の複素除算の精度（逆数 LUT の語長）。
ホスト側は `rt/isdbt` の等化後データ（`Xt`、`Wt`）を直接受け取る入口を作ればよく、参照実装（`ref/`）で
FPGA の固定小数点モデルをビット一致で検証する方針は v1 と同じ。

## 3b. 2b-1 の実装と結果（2026-10-14）

土台として「FFT テストモード」を実装した。モード 1 では窓切り出し（`rtl/isdbt_fe_win.v`、offset + k×stride、
decim で間引き）→ Xilinx FFT 9.1（8192 点、16bit、BFP、pipelined streaming、natural order）→
ヘッダ付き出力（`rtl/isdbt_fe_out.v`: MAGIC "ISBT"、blk_exp、64bit サンプルカウンタ、連番、8192 ビン）を
DMA に流し、モード 0 では従来どおり cpack の raw I/Q（`rtl/isdbt_dma_mux.v`）。制御は
`rtl/isdbt_regs.v`（0x3000 ブロック v2: CAPS / MODE / WIN_STRIDE / WIN_OFFSET / WIN_DECIM / FE_STATUS / FE_FRAMES）。

| 項目 | 結果 |
|---|---|
| 資源（7010） | LUT 11,002（63%）、FF 18,972（54%）、BRAM 44（73%）、DSP 25（31%）。BRAM は FFT の自然順並べ替えと出力 FIFO（2 窓）が大きい |
| シミュレーション | 振る舞いモデルでフレーミング PASS。実物 FFT IP（`rtl/isdbt_fe_xfft_tb.v`、`scripts/sim_fe_xfft.tcl`）で全窓一致 0.25 LSB rms |
| 実機（ループバック、isdbt-sdr `tools/fe_fft_test.py`） | raw 経路 258,048 サンプルがビット一致。FFT 出力は numpy FFT と相対 rms −72 dB（BFP 16bit の丸め）、逆 FFT の時間領域最大誤差 0.58 LSB、連番・サンプルカウンタの連続性 OK |
| 落とし穴 | **xfft（realtime）はフレーム先頭サンプルの直後に 1 サイクル tready を落とす。** 無視して流すと 2 サンプル目が欠け末尾が重複する（xsim で再現 → 窓エンジンに FIFO を入れて tready を守る） |
| 検証手法 | AD9361 のデジタルループバック（`loopback`=1）で既知の 12bit パターンを TX から巡回送信すると、RX の 12bit 値が TX と完全一致するので FPGA 内の処理をビット精度で検証できる。以降の 2b の段階（同期・等化）も同じ枠組みで、ref/ の合成 ISDB-T 信号を流して照合する |

## 3c. 2b-2 の実装と結果（2026-10-14）

モード 2（同期）: `rtl/isdbt_gi_corr.v`（8bit I/Q の GI 相関、遅延 8192 + 移動和 1024、numpy とビット一致）→
`rtl/isdbt_sync.v`（捕捉: 1 シンボル周期の最大探索 / 追従: 予測 ±64 の最大を 2^-4 で平均、ピーク位相から
小数 CFO を IIR 平均して NCO 増分、ロック監視）→ `rtl/isdbt_cordic.v`（atan2 と回転、12 段、内部 20bit）で
生サンプルを逆回転 → 窓エンジンは sync の開始要求（有効部分の 128 サンプル前）で窓を開く。
ヘッダの w6/w7 に CFO 増分とロック状態。整数 CFO はホスト側で処理する（ビンのシフト）。

| 項目 | 結果 |
|---|---|
| 7010 に収めるための削減 | 同期を足すと配置が溢れた（LUT 84%）ので、PL の I2C / PL 側 SPI / TDD を削除（dts は linux フォークで disabled。ADM1177 電流監視は AXI I2C 配下なので消える）、FFT を 12bit、CORDIC を 12 段に。**LUT 12,146（69%）/ FF 18,771（53%）/ BRAM 45（75%）/ DSP 25** |
| シミュレーション | `rtl/isdbt_sync_tb.v` + `scripts/make_sync_stimulus.py`（合成 ISDB-T に CFO 3.33 bin・−15.6 ppm）+ `scripts/check_sync_sim.py`: 40 窓追従、窓開始の揺れ std 2.4 サンプル、CFO 推定 0.3275（真値 0.3264）bin |
| 実機（ループバック、`tools/fe_sync_test.py`） | 間引き 4 で窓開始が毎回 36,864 ± 1、全窓ロック、CFO 推定 0.3302（真値 0.3333）bin、窓は有効部分の 144 サンプル前（GI 内）、逆回転込みの窓の中身が送信パターンと相対残差 2.6e-3（−52 dB）で一致 |
| 実機で見つかった不具合 | 回転器の出力が 4 倍のまま（事前スケールの桁戻し忘れ、飽和で歪む）、捕捉直後の過去位置の開始要求が FIFO に詰まって窓が出ない（過去の要求を常に捨てる）、Verilog の符号なし混在式で >>> が論理シフト、xsim の $fscanf "%d %d" が両方負の行で失敗 |
| 精度 | GI 相関ピークは雑音で ±30 サンプル揺れる（三角形の頂点が平坦なため）→ 平均化（α = 1/16）が必須。12bit FFT の丸めはフルスケール比 −59 dB |

## 3d. 2b-3a: 同期 FFT の 8bit 出力とホスト後段の接続（2026-10-14）

| 項目 | 内容 |
|---|---|
| モード 3 | モード 2（同期 FFT、16bit ビン）のビンを 12bit → 8bit に丸めて 2 ビン/ワードで出す（ヘッダ w1 bit24 = fmt）。1 窓 8 + 4096 ワード = 16.4 KB、882 窓/s = 14.5 MB/s で USB 2.0 に収まり間引きなしで全シンボルが出せる。量子化スタディ（`tools/fe_quant_study.py`）どおり 8bit ビンの MER 劣化は 0.1 dB 未満 |
| ホスト側 | `tools/fe_carrier_demod.py`: 連番が連続する区間をシンボル行列にし、帯域エネルギーの箱型相関で整数 CFO δ を求め、キャリア k をビン (carrier_to_fft_bin(k) + δ) mod N から取り、窓開始位置 s に応じた位相 e^{−j2πδs/N} を掛けて ref/ の frame_sync → 等化 → 復号へ渡す |
| 見つかった不具合（実機） | **入力が無音のときにモード 2/3 を入れると同期が永久に固まり、信号が来ても復帰しない。** 1 フレーム分（204 シンボル、7.5 MB）の TX ブロックは走り出すまで 0.3 s 以上かかるため、ホストが先にモードを入れて再現した（40 シンボル 1.5 MB では間に合っていた）。原因は 2 つ: (1) 捕捉窓の最大値が窓の先頭 W=64 サンプル以内にある（無音なら必ず先頭）と、追従の探索開始条件 `d_pred == −W` をすでに通り過ぎていて二度と探索が始まらない（実信号でも 0.7 %/捕捉）。(2) 無音で捕捉すると avg_peak = 0 になり、その後はどんな入力でも「ピーク ≥ avg_peak/4」が成り立つので誤った位置に固定される。SYNC_STATUS レジスタ（0x38、state / in_search / locked / miss / acq_fail / lock_losses）と SYNC_PEAK（0x3C）を足して実機で状態を読めるようにした |
| 対策（`rtl/isdbt_sync.v`） | 探索開始を `[pred − W, pred + W)` の範囲判定にし、`pred + W` を過ぎていれば pred を 1 シンボル進める。捕捉・追従とも「ピーク > シンボル内平均 × 9」（mag2 の和 >> 10、T/1024 = 9）を要求し、無音・雑音だけでは追従に入らない／追従中に信号が消えたら MISS_MAX 回で捕捉に戻る。シミュレーション（`isdbt_sync_tb` の `ZERO_PREFIX=20000`、`GAP=30000`）: 無音中は捕捉を 2 回棄却、信号到来でロック、ギャップでロック喪失 1 回、再ロック、窓位置・CFO とも PASS |
| ホストの待ち | `fe_sync_test.py` / `fe_carrier_demod.py` は TX 開始後 1.0 s 待ってからモードを入れる（FPGA 側の修正と独立に、試験の再現性のため） |
| 実機結果（修正版 `recovery/pluto-v0.39-isdbt-nano-v2b3b.frm`、2026-10-14） | TX 開始前にモードを入れても即ロック（SYNC_STATUS: TRACK / locked）。`fe_sync_test.py` 1 フレーム刺激 PASS（CFO 推定 0.3204、真値 0.3246 bin）。**ループバック TS 照合 PASS**: 3 フレーム巡回刺激（612 シンボル、22.5 MB、C/N 30 dB）で 2682 窓を取りこぼしなく取り込み、MER A/B 29.8 dB、B 層は変調器の TS と 66.9 % 一致・最長連続一致 5414 パケット（= 2 フレーム。巡回の継ぎ目をまたぐ 1 フレームは時間インターリーブが合わないので 2/3 が理論上限）。**実波 ch 24**: MER A 28.4 / B 23.9 dB、RS 訂正不能はデインターリーブ履歴分の 11 パケットのみ（ホスト全段パイプラインの 23〜30 dB と同等） |
| ホスト側で必要だった補償（2b-3b の FPGA 等化器にも同じ処理が要る） | (1) **窓位置の揺れ**: 追従は窓開始を整数サンプルで動かすので（雑音で ±2〜5 サンプル/シンボル）、帯域端のビンは 1 サンプルで 2.1 rad 回り、チャネル推定の時間平均・補間が壊れる（補償前: A 17 dB / B −16 dB）。直線フィットからの偏差 Δ_n をビン b に e^{−j2π b Δ_n / N} で打ち消す。直線分（クロック偏差で窓が流れる分）は消してはいけない（追従した窓は信号に対して静止しているので、消すと逆に「流れる窓」になり B 層 19 → 15 dB に悪化した）。(2) **残留 CFO**: NCO の小数 CFO 推定に 0.005〜0.016 bin の誤差が残り、シンボルごとの共通位相回転（0.016 bin で 0.11 rad/シンボル）になる。パイロット位置は自シンボルで補正されるので MER 29 dB のままだが、8 シンボル平均の推定格子（隣の格子点は別シンボル由来）がジグザグになりデータキャリアの補間だけ崩れる（A/B 13〜17 dB）。SP が 4 シンボル周期で同値なことを使い Σ_k Y[n+4,k]·conj(Y[n,k]) の位相/4 を平滑化・積算して逆回転する。(3) 整数 CFO δ の窓位置依存位相 e^{−j2πδ s_n/N} |
| 試験データの落とし穴 | `testdata/synthetic/`（2026-10-02 生成）は現在の ref/ で B 層の RS が全滅する古いものだった（`make synth` で再生成すると正常）。刺激は再生成後のものから作ること |

## 3e. 2b-3b: FPGA 等化器（モード 4）の設計（2026-10-14 着手）

ホスト側で必要だった補償（3d 節）をそのまま FPGA に移す。アルゴリズムは `isdbt-sdr tools/fe_eq_model.py`
（`--cpe-own --fpga-timing --fixed`）でモデル化し、実波録音の定常状態で ref/ 浮動小数点等化に対し
**A −0.24 dB / B −0.10 dB**（RS 誤り同一）、ループバックで −0.6〜−1.0 dB（短い録音で時間軸推定が
最終段に達していないため）。立ち上がり（時間軸の最初のブロック 256 シンボル ≈ 0.3 s）は B 層が崩れる。

| 要素 | 方式 |
|---|---|
| 時間軸（`isdbt_sync` tim_delta） | 追従器の窓開始は ±2 サンプル揺れる上に数百シンボル周期で ±1 さまよう。T_est = (pred_n − pred_{n−2^L})/2^L（L = 8 → 10 → 12 → 13、以後 IIR 1/2）でシンボル長を推定し、τ += T_est の帰還なし直線を時間軸にする。Δ_n = s_n − τ_n（1/256 サンプル、mod N·256）。2 次ループ（K1=2^-12 等）は −16 ppm の引き込みが遅く不採用 |
| パス A（受信、8192 サイクル） | ビン b を e^{j2πθ}（θ = −bΔ_n/N − δ·s_n/N − φ_afc）で回す。sin/cos 表 1024 × 32bit + 複素乗算（CORDIC より LUT が少ない）。同時に 4 候補の SP エネルギーで SP 位相（n mod 4）を検出 |

## 3f. 2b-3c: ホスト rt/ と BonDriver の接続、モード切替のリセット（2026-10-15）

`tools/fe_eq_test.py` と同じ: raw I/Q でソフト AGC 約 1 秒 → モード 3 の 16 窓から整数 CFO δ →

**モード 0 → 再開でフレームがずれるバグ（eq5 まで）**: 選局（Retune）のたびにモード 0 → 3 でやり直すと、
モード 3 のフレームが 1.5 窓分の長さになり seq が 1 つおきに飛び、δ 推定が −100（帯域が見えない）になる。
運よく揃うまで 1〜4 回（各 1.3 s）の再試行が要った。原因は 2 つ:
(1) 窓の途中で止めると xfft が未完のフレームを抱え、再開後の最初の窓がその続きになる（以後ずっとずれる）。
(2) `isdbt_fe_out` が `!enable` で読み出し側（sk_rd / exp_rd）だけ戻し、書き込み側（sk_wr / exp_wr / frame_first）を
戻していなかった。対策: `isdbt_fe_win` が `fft_aresetn` を出し、モード 0 の間 xfft をリセットに保って再開時に設定
（FWD_INV）を送り直す。fe_out は書き込み側と pk_half も戻す。`rtl/isdbt_fe_xfft_tb.v` に「4 窓目の途中でモード 0 →
再開」の段階を足し、実物 xfft IP で 6 フレームとも長さ正常（PASS）。hdl フォークは `fe_fft/aresetn` を
`logic_inv` から `fe_win/fft_aresetn` に（c56754e）。

**eq6 ファーム（`recovery/pluto-v0.39-isdbt-nano-v2b3c-eq6.frm`、WNS +1.21 ns、LUT/BRAM/DSP は eq5 と同等）の実機結果（06:00）**:
isdbtd で 24 → 22 → 24 と選局して 3 回とも再試行なしで δ = 9 を得てモード 4 に入った（eq5 では 1〜4 回の再試行）。
同時刻の MER は FPGA 経路 A 17〜21 / B 19〜21 dB、raw ホスト復調 A 24 / B 24.6 dB で、eq5 に戻しても A 20.8 / B 20.8 dB
だった → 低下は eq6 のせいではなく受信条件（朝方）。**FPGA 経路と raw の差が時間帯で −0.7 → −1.7 → −3.5 dB と広がる**のは
未解明（AGC 固定、AFC ω が 0.013 → 0.033 bin に増えている、多重波の変動のどれか）。次の課題。
